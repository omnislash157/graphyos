# a relations-only declaration change is named stale until build, never served from the old relations row
issue: graphyos #115
host: linux
scars: S1 S8 S4 S5 S7

## Contract
- C1 a lane that re-declares only `vocabulary.relations` over unchanged shards makes `open_for` refuse, naming the moved relations and `graphy build`
- C2 under `on_stale=warn` the same store says STALE on stderr and serves
- C3 `graphy check` reads the moved declaration as a red store finding
- C4 after `graphy build` the store opens and `blast` follows the new declaration
- C5 a store whose relations row already matches the fold opens as before, so an upgrade over an unchanged tenant is fresh
- C6 the generation does not change for a relations-only edit, so stored walks under it stay keyed
